The Predictable Container Rule

            
In cloud computing, software containers are supposed to be predictable and repetitive. A container running PostgreSQL executes query routines millions of times a day; it should never suddenly spawn an interactive shell (/bin/sh) or connect to an outbound IP to download payloads.

            
Instead of relying on opaque, unpredictable AI guesses or noisy static CVE scanners, Porygon watches the Linux operating system directly, measures mathematically how far live behavior deviates from baseline, and produces auditable, deterministic incident evidence.

          


          

            
eBPF & Kernel Syscall Ingestion

            
Porygon attaches eBPF ring buffers directly to sys_enter_execve inside the Linux kernel. Every process spawned by any container is captured with zero userland binary modification.

            

              
Falco kernel eBPF probe → /var/log/porygon/falco-events.jsonl

              
Telemetry Adapter (spool outbox.db) → POST /internal/v1/process-events/batch

              
PostgreSQL 17 (process_exec_events) • overhead not yet measured (MET-CPU-001)

            

          


          

            
Information-Theoretic Jensen-Shannon Distance

            
Porygon scores deviation between baseline distribution P and live distribution Q using the symmetric, finite base-2 Jensen-Shannon distance:

            

              
M = 0.5 × (P + Q)

              
D_JS(P || Q) = sqrt( 0.5 × D_KL(P || M) + 0.5 × D_KL(Q || M) )

              
Categorical (50%) + Novelty (30%) + Robust Z (20%) = D_JS ∈ [0.00, 1.00]

            

            
Threshold 0.50 triggers POR-DET-001. Score 0.75+ triggers extreme deviation alert.

          


          

            
4-Stage Vulnerability Reachability Funnel

            
Traditional scanners report thousands of CVEs on disk that are never loaded into memory. Porygon correlates image SBOMs with live eBPF process execution:

            
    
              
  • Stage 1 (package_present): Component exists inside image files on disk.
    • 
              
  • Stage 2 (deployed): Container running image digest is active on host.
    • 
              
  • Stage 3 (runtime_observed): eBPF observed the vulnerable binary executing in RAM.
    • 
              
  • Stage 4 (port_published): Container has public listening port exposed to the network.
    • 
            

          


          

            
The 7 Deterministic Detection Rules

            

              

                POR-DET-001
                
Statistical D_JS Drift

                
Divergence score exceeds 0.50 threshold against learned profile.

              

              

                POR-DET-002
                
Unseen Interactive Shell

                
Spawns /bin/sh, /bin/bash, or dash not in container baseline.

              

              

                POR-DET-003
                
Novel Root Execution

                
UID 0 process executes inside an unprivileged container.

              

              

                POR-DET-004
                
Network Discovery Probes

                
Invocation of network probing utilities (nc, nmap, netcat).

              

              

                POR-DET-005
                
Shell-to-Tool Sequence

                
Shell spawns downloader (wget, curl) within 120s window.

              

              

                POR-DET-006
                
Log Wiping / Anti-Forensics

                
Process clears /var/log or audit trails via redirection.
