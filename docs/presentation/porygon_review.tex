\section{The Problem}
\begin{frame}{The Problem}
\framesubtitle{Behavioural profile scoping is an unresolved design parameter, not a solved problem}

\begin{columns}[T]
\column{0.52\textwidth}
\small
Container process-execution anomaly detection observes the syscalls a
containerized process issues (via eBPF/Falco), builds a baseline of
``normal'' process-name activity, and flags deviating execution events.
Falco, Sysdig Secure, Aqua, and academic work since Forrest et al.\ (1996)
already do this; the sensor and scoring primitive are established, not novel.

\medskip
What every implementation must still decide, without a published answer, is:
\emph{at what identity granularity is the baseline scoped?} Per fleet
(global), per mutable tag, per exact image digest, or per digest plus
runtime security configuration? Vendors pick one by engineering judgement.

\medskip
\textbf{The unresolved question.} No published, reproducible, statistically
powered comparison of these four scoping strategies exists.

\column{0.46\textwidth}
\centering
\begin{tikzpicture}[node distance=4mm]
  \node[box, accent, minimum width=34mm] (app) {Container process\\ \tiny execve/execveat stream (Falco)};
  \node[box, below=6mm of app, minimum width=34mm] (norm) {Baseline distribution\\ \tiny process-name counts, fit split};
  \node[box, below=6mm of norm, minimum width=34mm, amber] (odd) {Jensen-Shannon distance $\geq$ threshold};
  \node[box, below=6mm of odd, minimum width=38mm, blue] (q) {Which baseline scope minimizes\\ false positives without losing recall?};
  \draw[fl] (app) -- (norm);
  \draw[fl] (norm) -- (odd);
  \draw[fl] (odd) -- (q);
\end{tikzpicture}

\smallskip
{\scriptsize A stratum with too few independent fit-split runs returns
\texttt{insufficient\_profile} explicitly, never a guessed score.}
\end{columns}
\end{frame}

% ============================================================
% RESEARCH QUESTION
% ============================================================
\begin{frame}{The Research Question}
\framesubtitle{Four scoping arms, one frozen protocol, pre-registered statistics}

\begin{columns}[T]
\column{0.45\textwidth}
\footnotesize
An OCI image digest (\texttt{repository@sha256:<64 hex>}) is an immutable,
content-addressed identity: the exact same bytes always resolve to the same
digest, unlike a mutable tag such as \texttt{nginx:latest}, which can be
silently repointed to a different image.

\medskip
\textbf{H1 (primary):} does scoping the baseline by digest + runtime security
context (\texttt{ARM-CONTEXT}) reduce the benign false-positive rate versus
digest-only scoping (\texttt{ARM-DIGEST}), without a material loss of
detection recall on planted attack scenarios?

\medskip
\textbf{Runtime context} is a canonical SHA-256 hash over: entrypoint/command
shape, effective user, \texttt{privileged}, \texttt{read\_only\_rootfs},
network mode, Linux capabilities added/dropped, devices, published ports, and
mounts -- security-relevant configuration \texttt{docker inspect} exposes,
excluding secrets and literal argument values.

\column{0.53\textwidth}
\centering
\resizebox{\linewidth}{!}{%
\begin{tikzpicture}[node distance=3mm]
  \node[box, accent, minimum width=48mm] (img) {\texttt{repository@sha256:<digest>}};

  \node[box, below left=9mm and 6mm of img, minimum width=26mm] (d1) {\texttt{ARM-GLOBAL}\\ \tiny pooled across all images};
  \node[box, below=9mm of img, minimum width=26mm] (d2) {\texttt{ARM-TAG} / \texttt{ARM-DIGEST}\\ \tiny mutable alias / exact digest};
  \node[box, below right=9mm and 6mm of img, minimum width=26mm] (d3) {\texttt{ARM-CONTEXT}\\ \tiny digest + config hash};

  \draw[fl] (img) -- (d1);
  \draw[fl] (img) -- (d2);

  \node[box, blue, below=9mm of d2, minimum width=60mm] (q)

  \draw[fl] (d1) -- (q);
  \draw[fl] (d2) -- (q);
  \draw[fl] (d3) -- (q);
\end{tikzpicture}}

\smallskip
{\scriptsize No fallback between arms during primary analysis. A null result
for H1 is reported as a null result, not concealed by a weaker contrast.}
\end{columns}
\end{frame}

\begin{frame}{What Makes Porygon Different}
\framesubtitle{A measured answer to a question every commercial runtime-security product answers by guesswork}

\begin{columns}[T]
\column{0.5\textwidth}
\footnotesize
\textbf{Built on established, production-grade components:}
\begin{itemize}\setlength\itemsep{2pt}
  \item Falco 0.44.1 eBPF kernel telemetry -- the same sensor engine
        deployed in production by Sysdig, Aqua, and CNCF-graduated
        security stacks
  \item Jensen-Shannon information-theoretic divergence -- the same
        distance measure used in published network-traffic anomaly
        detection (Salem \& Naït-Abdesselam, IEEE ICC 2012)
  \item SHA-256 content-addressed image identity -- the OCI-standard
        supply-chain integrity mechanism
  \item Live EPSS (FIRST.org) and CISA KEV feed correlation on every
        scanned CVE
\end{itemize}

\medskip
\textbf{The unanswered industry question:} every one of these products
ships a behavioral baseline. None of them publish a controlled measurement
of \emph{how tightly that baseline should be scoped} -- one profile per
fleet, per tag, per exact image, or per image-plus-configuration. Vendors
ship a default and move on. Porygon measures it.

\column{0.5\textwidth}
\footnotesize
\textbf{What Porygon adds:}
\begin{enumerate}\setlength\itemsep{2pt}
  \item A frozen, pre-registered protocol running the same telemetry and
        rules through four baseline-scoping strategies, measured with
        exact statistics (McNemar, Holm-Bonferroni, Clopper-Pearson) --
        not a single reported accuracy number.
  \item A decisive result: per-image scoping eliminates false alarms
        entirely versus a pooled baseline (100\%~$\to$~0\%,
        $p=6.7\times10^{-16}$) with zero loss of detection recall.
  \item A new feature built directly from that result: scoring the
        container's security configuration (privileges, capabilities,
        mounts) as its own signal -- 0 false alarms, 100\% detection
        of every tested configuration change, $n=53$.
  \item Live-fire validation against a real, published malware sample
        (next slide), not a synthetic test script.
\end{enumerate}
\end{columns}
\end{frame}

\begin{frame}{1. Methodology --- The Scoring Mathematics}
\framesubtitle{Rubric: Mathematical Model / Formulation (5 Marks)}

\begin{columns}[T]
\column{0.53\textwidth}
\footnotesize
\textbf{Production path (generates every reported number).}\\
Base-2 Jensen-Shannon distance between baseline $p$ and observed-window $q$:
\vspace{-1mm}
\[ D_{JS}(p\Vert q)=\sqrt{\tfrac12 D_{KL}(p\Vert m)+\tfrac12 D_{KL}(q\Vert m)},\quad m=\tfrac{p+q}{2} \]
\vspace{-2mm}

Bounded $[0,1]$ (base-2 log); 0 = identical. Empty observed window returns
\texttt{None} (excluded, not zero); empty baseline vs.\ non-empty observation
returns 1.0.

\medskip
\textbf{Aggregation} (\texttt{scoring.py}, algorithm \texttt{porygon.distance.v1},
fixed weights, versioned):
\[ \text{score}=0.50\cdot\overline{D_{JS}}_{6\text{ families}}
  +0.30\cdot\text{novelty}+0.20\cdot\overline{z}_{5\text{ numeric}} \]

Categorical weights: process name 0.15, executable 0.25, parent-child 0.20,
UID 0.10, runtime action 0.10, sequence bigram 0.20. Missing family excluded,
remaining weights renormalized, never imputed as zero.

\medskip
\textbf{Study threshold:} $D_{JS}\geq 0.25$ = positive call
(\texttt{DEFAULT\_THRESHOLD}).

\column{0.45\textwidth}
\footnotesize
\textbf{Exploratory alternative, not used for any reported number:}
\texttt{calibrated\_rarity.py} implements unweighted-mean fusion over 4
components and a conformal-style exceedance p-value:
\[ p=\frac{1+\#\{\text{calib.\ values}\geq\text{test}\}}{n+1} \]
Feature-flagged (\texttt{calibrated\_enabled}, default \texttt{False}); the
study used the production JS-distance path, not this module.

\medskip
\textbf{Not a probability.} A JS-distance or fused rarity value is a
distributional-deviation measure. Neither module documents or claims a
$P(\text{attack})$ field.

\smallskip
{\scriptsize\textcolor{warnAmber}{\textbf{Honest limitation:}} the
0.50/0.30/0.20 weights are a fixed implementation decision, not fit to
data -- disclosed, which is why the unweighted alternative exists.}
\end{columns}
\end{frame}

\begin{frame}{2. Implementation Progress --- The Safety Rails Work}
\framesubtitle{Refusal paths that prevent an unsupported result from being reported}

\begin{columns}[T]
\column{0.5\textwidth}
\footnotesize
Three refusal paths that prevent an unsupported or contaminated result from
silently becoming a reported number:

\medskip
\textbf{1. \texttt{insufficient\_profile}, not a guessed score.}\\
When a scope key (e.g.\ a digest with zero fit-split coverage) has no
reference distribution, \texttt{score\_trial\_under\_scope} returns
\texttt{reference\_key\_present=False} and the trial is excluded from
FPR/recall counts, never scored as either a pass or a detection
(\texttt{experiments/scope.py}).

\medskip
\textbf{2. Fit/test overlap rejection.}\\
Scoring a window that overlaps the interval used to build that same baseline
is rejected at the API layer, preventing a model from being evaluated on its
own training data.

\medskip
\textbf{3. Mutable-reference rejection in the experiment harness.}\\
Pulling a workload image by tag instead of a resolved
\texttt{repository@sha256:<digest>} coordinate is rejected before the pull
(\texttt{experiments/real.py:pull\_pinned\_image}), so no trial can silently
run against an unpinned image.

\column{0.48\textwidth}
\centering

& Picking a threshold and reporting the resulting accuracy directly \\

Whole-run split assignment
& Adjacent windows in one run are near-duplicates; window-level splitting would overstate confidence
& Random assignment of individual time windows \\

Operator-token-gated containment
& A false positive must never autonomously disrupt a healthy service
& Automated pause/stop triggered directly by score \\

\midrule

\begin{itemize}\setlength\itemsep{1pt}
  \item Backend outage $\rightarrow$ SQLite outbox spool, exponential backoff retry
  \item Sensor restart $\rightarrow$ durable telemetry cursor, no rewind
  \item Duplicate delivery $\rightarrow$ deterministic event ID, upsert
  \item Malformed input $\rightarrow$ kept as a short, scrubbed sample
  \item Too little data $\rightarrow$ answer ``insufficient'', never guess
  \item Runtime-context fingerprint redacts secret-shaped flags/values;
        raw process \texttt{command\_line} is stored as-is, not redacted

\begin{frame}{3. Technical Knowledge --- Confirmatory Result (n=144)}
\framesubtitle{Rubric: Preliminary Observations (5 Marks) --- measured on 144 real container trials}

\begin{columns}[T]
\column{0.49\textwidth}
\footnotesize
\textbf{1. \texttt{ARM-CONTEXT} vs \texttt{ARM-GLOBAL}: significant.}\\
\texttt{ARM-GLOBAL} (nginx/redis/postgres pooled into one reference)
produced a positive call on 35/35 held-out benign runs (FPR 100\%, 95\% CI
90.0--100\%). Per-image scoping (\texttt{ARM-CONTEXT}) reduced this to 0/35
(FPR 0\%, CI 0--10.0\%). Exact McNemar $p=5.8\times10^{-11}$, Holm-adjusted,
recall non-inferior (62/62 both arms). This is the frozen protocol's H1
contrast; it tests pooling vs.\ per-image scoping, not context specifically.

\medskip
\textbf{2. \texttt{ARM-CONTEXT} vs \texttt{ARM-DIGEST}: null.}\\
The paper's actual thesis -- does runtime-context conditioning add anything
beyond exact digest identity -- returns $p=1.0$: zero discordant pairs, both
arms agree on all 35 held-out trials. \texttt{ARM-CONTEXT} beating
\texttt{ARM-GLOBAL} above must not be cited as support for this claim; the
contrast that actually tests it is a null result.

\column{0.49\textwidth}
\footnotesize
\textbf{3. Root cause of the null result.}\\
The tested context variant (dropping Linux capability \texttt{NET\_RAW})
changes container privilege, not which processes execute. The categorical
\texttt{process\_name} feature cannot reflect a capability-only change by
construction, independent of scope.

\medskip
\textbf{4. Exploratory follow-on, same dataset, no new trials.}\\
\texttt{context\_delta.py} scores the runtime-context document directly
(\texttt{privileged}, \texttt{capabilities}, \texttt{read\_only\_rootfs},
\texttt{network\_mode}, mounts, devices) instead of inferring it through
process names: \textbf{0/18 FPR [CI 0--18.5\%], 17/17 detection of
\texttt{dropped\_capabilities} [CI 80.5--100\%]}. Hand-fixed weights, not
fit; not evaluated against attack scenarios; not confirmatory.

\smallskip
\textcolor{amritaMaroon}{\textbf{Why this matters:}} a mechanistically
understood null beats an unexplained positive.
\end{columns}
\end{frame}
