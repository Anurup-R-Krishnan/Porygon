\section{Research Question}
\begin{frame}{Research Question and Contribution}
\framesubtitle{The specific, falsifiable question this project answers}

\footnotesize
Container runtime anomaly detection (Falco, Sysdig, Aqua, and the academic
line from Forrest et al. 1996 through Abed/Clancy 2015) all build a
behavioural baseline of ``normal'' process activity and flag deviation.
None of them publish a controlled measurement of \textbf{at what identity
granularity that baseline should be scoped}: one profile per fleet
(\texttt{ARM-GLOBAL}), per mutable tag (\texttt{ARM-TAG}), per exact
immutable image digest (\texttt{ARM-DIGEST}), or per digest plus the
container's runtime security configuration (\texttt{ARM-CONTEXT}).
Vendors and prior work pick one by engineering judgement.

\medskip
\textbf{This project's contribution:} a frozen, pre-registered protocol
that runs identical Falco/eBPF telemetry and identical deterministic
detection rules through all four scoping strategies on the same real
Docker-container trials, and reports the false-positive-rate and recall
outcome of each with exact statistical inference (McNemar's test,
Holm-Bonferroni correction, Clopper-Pearson intervals) -- not a single
reported accuracy figure.

\medskip
\textbf{Confirmed result (216 real Docker-container trials, 53 held-out
benign runs, 96 planted-attack runs):} scoping per image
(\texttt{ARM-CONTEXT}) eliminates the false-positive rate entirely against
a pooled baseline, $100\%\to0\%$ ($p=6.7\times10^{-16}$), with zero loss
of detection recall (96/96 both arms). This is a statistically decisive,
reproduced result (first measured at $p=5.8\times10^{-11}$ on 144 trials,
confirmed at $p=6.7\times10^{-16}$ on the full 216-trial run).
\end{frame}

        \footnotesize
        \textbf{Methodological Framework:}
        \setlength{\abovedisplayskip}{4pt}
        \setlength{\belowdisplayskip}{4pt}

        \begin{itemize}
            \setlength{\itemsep}{5pt}

            \item \textbf{Behaviour Baseline:}
            Historical Docker lifecycle and Falco process events form a
            versioned baseline for one immutable image digest.

            \item \textbf{Anomaly Scoring:}
            For each categorical feature, the v1 scorer compares baseline $P$
            with a completed runtime window $Q$ using base-2 Jensen--Shannon
            distance:
            \[
                D_{\mathrm{JS}}(P,Q)
                = \sqrt{\mathrm{JSD}(P,Q)}
            \]
            Smaller values indicate more similar behaviour.

            \item \textbf{Rule-Based Detection:}
            Seven deterministic rules produce explainable findings. An incident
            requires an unsuppressed, incident-eligible finding.
        \end{itemize}

\begin{frame}{1. Methodology \& Solution Design (contd.)}
    \framesubtitle{Rubric: Methodology, Implementation Approach \& Design Choices (5 Marks)}

    \footnotesize
    \textbf{Implementation Approach and Design Choices:}

    \begin{itemize}
        \setlength{\itemsep}{7pt}

        \item \textbf{Kernel-Level Monitoring:}
        Falco's modern eBPF driver captures container process execution without
        modifying the applications. The Telemetry Adapter ingests those events,
        while the Docker Collector records lifecycle and image-identity events.
        Both use bounded SQLite outboxes with retry delivery.

        \item \textbf{Service Integration:}
        Docker Compose coordinates eight long-running containers. Segregated
        networks restrict connectivity, and outbound access is limited to the
        vulnerability scanner.

        \item \textbf{Explainable Analysis:}
        Base-2 Jensen--Shannon distance provides a bounded, symmetric measure of
        categorical change. Fixed rules expose the matched evidence, so the
        implemented path does not depend on a black-box ML classifier.

        \item \textbf{Controlled Response:}
        Policy thresholds use severity and confidence to determine allowed
        containment actions. Disruptive execution is disabled by default. When
        enabled, it still requires explicit human approval.

        \item \textbf{Implementation Verification:}
        The repository contains 79 backend test functions across baseline,
        scoring, detection, calibration, response, and vulnerability modules,
        plus 131 further test functions across the collector, telemetry,
        responder, and scanner services (210 total).
    \end{itemize}
\end{frame}

\section{Technical Knowledge}
\begin{frame}{3. Technical Knowledge \& Design Decisions}
    \framesubtitle{Rubric: Understanding of Methodology, Implementation \& Design Choices (5 Marks)}
    \footnotesize
    \begin{itemize}
        \item \textbf{Algorithmic Justification:} JSD is used over raw KL divergence because it is symmetric ($JSD(P,Q)=JSD(Q,P)$) and bounded, giving comparable scores across containers. Deterministic rules are used instead of a trained ML classifier because the system is explicitly designed around mathematical distance measures, not black-box classifiers, for explainability.
        \item \textbf{Mathematical Formulation:} The Response Policy Engine computes:
        \[
        \text{Action} =
        \begin{cases}
        \text{stop} & \text{if } Sev \geq 0.90 \wedge Conf \geq 0.75 \wedge (\text{POR-DET-005} \vee \text{POR-DET-007}) \\
        \text{pause} & \text{if } Sev \geq 0.70 \wedge Conf \geq 0.55 \\
        \text{observe only} & \text{otherwise}
        \end{cases}
        \]
        \item \textbf{Confirmed Statistical Result:} the frozen protocol's
        primary hypothesis test (per-image scoping vs.\ pooled baseline) is
        significant at $n=216$: exact McNemar $p=6.7\times10^{-16}$
        (Holm-adjusted), false-positive rate $100\%\to0\%$, recall
        non-inferior (96/96 both arms).
    \end{itemize}
\end{frame}

\begin{frame}{3. Technical Knowledge \& Design Decisions (contd.)}
    \framesubtitle{Rubric: Understanding of Methodology, Implementation \& Design Choices (5 Marks)}
    \footnotesize
    \begin{itemize}
        \item \textbf{Design Choices \& Trade-offs:}
        \begin{itemize}
            \item \textbf{Multicall binary handling:} BusyBox/Toybox-style binaries are matched applet-aware, avoiding false positives from one executable exposing many command names.
            \item \textbf{Canonical scan identity:} Vulnerability scans are keyed by a SHA-256 hash of 6 parameters (image digest, local image ID, scanner name, scanner version, vulnerability schema version, researcher scan reference), making scans idempotent and immutable.
            \item \textbf{Network segregation:} Services run across three isolated Docker networks (ingress / internal / egress) with least-privilege socket access.
            \item \textbf{Fixed, versioned scoring weights:} every historical score stays reproducible under a named algorithm version; a weight change requires a new version, never a silent edit.
        \end{itemize}
        \item \textbf{Confirmed Findings (216 real trials, exact statistical pipeline):}
        \begin{itemize}
            \item Per-image scoping vs.\ pooled baseline: significant, $p=6.7\times10^{-16}$, FPR $100\%\to0\%$, recall unchanged.
            \item Digest-plus-context vs.\ digest-only: no measurable difference in this dataset, $p=1.0$, reproduced at both $n=35$ and $n=53$ -- traced to the tested configuration change (a dropped Linux capability) not altering which processes execute, which the process-name feature cannot see by construction.
            \item Follow-on feature scoring the security-configuration document directly separates every tested case cleanly: 0/26 false positives, 27/27 correct detections.
        \end{itemize}
    \end{itemize}
\end{frame}
