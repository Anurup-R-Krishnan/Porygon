## Steps

### Step 1: Define immutable experiment artifacts

Create JSON Schemas for experiment, trial, workload, scenario/ground truth, profile scope, model/calibration, telemetry-quality snapshot, resource sample, result, and analysis manifest. Every record includes protocol/run/trial IDs, Git SHA, dirty-state flag, image digests, Compose/config hashes, kernel/Docker/Falco/service versions, architecture, random seeds, UTC monotonic timing anchors, and parent artifact hashes. Never store credentials or environment values.

The runner writes atomically, resumes by immutable trial ID, never overwrites a completed trial, and records failed/interrupted trials with reason. Analysis reads only validated artifacts, not live databases.

**Verify**: schema tests reject missing provenance, secret-like fields, mutable tags without resolved digest, cross-split run reuse, hash mismatch, and result files without raw parents.

### Step 2: Implement deterministic workloads and safe scenarios

Implement the exact Plan 003 workload families/versions and request/query generators. Pin images by digest for confirmatory runs. Each trial creates isolated names/networks/volumes, waits for readiness, records ground-truth timestamps before and after the action, and cleans up only its own validated resources.

Implement hard negatives and safe attack simulations from the protocol. Shell/tool scenarios run only inside disposable labelled containers. Event-flood and outage scenarios have fixed caps/timeouts. Baseline-poisoning is a separate experimental arm and can never contaminate primary fit/calibration artifacts.

**Verify**: two runs with the same seed produce identical action schedules/manifests; different seeds differ only in declared randomized fields. Cleanup refuses broad/unresolved targets.

### Step 3: Attribute telemetry loss and end-to-end performance

Generate sequence-numbered canaries and reconcile each observable boundary. Sample Falco/kernel counters where Falco exposes them; where a boundary is not observable, emit `unmeasured` with reason, never zero. Persist service restart/reset epochs so process-local counters are not added across resets incorrectly.

Use monotonic clocks for durations and UTC timestamps for cross-service traceability. Record latency percentiles from raw per-event timestamps, not averages of service summaries. Sample CPU-seconds/RSS/I/O from a documented host mechanism at a fixed interval, and measure workload latency with a deterministic load generator. The measurement process’s own resource cost must be reported.

Run steady 25/100/250 events/s, 1,000 events/s burst, and outage/recovery smoke-sized trials first.

**Verify**: injected synthetic loss at each supported boundary is attributed to that boundary; duplicates never count as loss; counter reset/restart fixtures do not produce negative or impossible totals.

### Step 4: Implement profile/detector comparisons and ablations

Fit/calibrate/test all four profile scopes on identical run assignments. Run rules-only, novelty-only, frequency-only, sequence-only, calibrated v2 anomaly-only, and hybrid detectors. Execute every frozen ablation without altering the underlying evidence set. Include same-image replicas, different runtime contexts, version drift, and cross-workload misapplication.

Thresholds/tuning use fit/calibration only. Confirmatory test labels remain hidden from tuning code until outputs are frozen. Analysis operates at run level, reports confidence intervals and sample counts, and includes insufficient-profile/calibration failures rather than dropping them.

**Verify**: a leakage test intentionally reuses a run across splits and must fail; each comparison manifest proves identical trial IDs/evidence hashes across arms where required.

### Step 5: Generate paper tables, plots, and an attribution report

Create deterministic scripts that generate every claim-mapped table/figure from raw validated artifacts. Required outputs include profile-scope comparison, detector comparison, ablations, hard-negative errors, per-scenario results, calibration coverage, latency/loss/overhead, scalability curves, and failure/limitation inventory. Include uncertainty and exact `n`; never report a percentage without numerator/denominator.

Generate a performance attribution report ranking hotspots by measured contribution and identifying the first macro-optimization candidate. It must include before values and a separately frozen post-optimization protocol for a later plan; do not implement the optimization now.

**Verify**: replay analysis twice in clean temporary directories; normalized CSV/JSON/table data hashes match. Plot metadata links to source tables and does not embed hidden manual edits.

### Step 6: Run smoke, review, then execute confirmatory study

Run the tiny smoke matrix, inspect safety/provenance/measurement perturbation, and obtain protocol-owner approval. Freeze code/config/image hashes. Run the full confirmatory matrix without changing them; resume interrupted trials rather than rerunning selectively. Record environment failures as failures.

**Verify**: `python3 experiments/validate_artifacts.py <run-root>` passes; all expected trial IDs are completed or explicitly failed; the analysis manifest accounts for every trial and claim.

## STOP conditions

- Any dependency plan is not `DONE`, v2 calibration semantics do not match the frozen protocol, or the live host lacks Docker/BTF/Falco support.
- A required image cannot be pinned/resolved, a workload is non-deterministic, or ground truth cannot be timestamped reliably.
- Measurement overhead materially changes the workload and cannot be quantified/reduced.
- Loss cannot be reconciled and the harness is tempted to assume a missing boundary is zero.
- Confirmatory results have been observed and someone proposes changing a threshold, exclusion, workload, or hypothesis in place.
- Cleanup target resolution is broad, ambiguous, or could affect non-experiment resources.
